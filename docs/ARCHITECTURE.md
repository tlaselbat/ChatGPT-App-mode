# Architecture and current behavior

## Runtime layout

The maintained source lives at the project root, in `extension/`, `tools/`, `WindowHost/`, and `TaskbarLauncher/`. The pinned Electron runtime (`node_modules/electron`) and the dedicated host profile (`Browser/AppModeHostProfile`) are local runtime state. `logs/` contains operational logs and restorable session/recent-chat metadata. Local configuration is `config.json`; `config.example.json` is the sanitized template. ZIP installers, package builds, `.lnk` shortcuts, and `archive/` contents are generated or machine-specific artifacts.

## Launch flow

`Launch-ChatGPT-AppMode.ps1` starts the tray helper and topmost loopback server, loads local configuration and shared helper functions, and starts the Electron host via `Start-AppModeNativeHost` with `WindowHost/main.cjs`. `windowHost` is `electron` — the only supported runtime; a missing runtime or immediate startup failure warns and aborts. The installer creates configuration and shortcuts, installs the Electron runtime, and may rebuild the taskbar launcher.

`Reset-AppMode-HostProfile.ps1` targets only `Browser/AppModeHostProfile`. It requires typed confirmation, refuses running host processes, validates the dedicated Browser boundary, and rejects runtime software (`node_modules/electron`), path aliases, and reparse points (including descendants). Tests invoke the guards without invoking deletion.

`tools/AppMode.State.ps1` owns configuration merging, atomic JSON writes, history policy, startup shortcuts, reset guards, and screen-bound clamping. `tools/AppMode.Windows.ps1` owns native window access and executable/profile/HWND/PID validation. `Open-AppMode-Settings.ps1` supplies a native settings surface; saving preserves unrelated configuration. Installers merge missing defaults instead of regenerating source.

## Shared override entry points

The host injects `extension/styles/chatgpt-overrides.css` and concatenates the ordered classic scripts listed in `extension/manifest.json` into ChatGPT pages, then injects `WindowHost/header.css`/`header.js` for defensive contextual-header compatibility. MV3 uses the same ordered script list for Playwright fixture and live-audit browser contexts. The shared page-local context owns lifecycle, sidebar, home layout, Share, Pin/session, and event coordination; repeated initialization in one document is ignored. The scripts add a body marker, set the document title, create the always-on-top button, report eligible current URLs to the local session endpoint, and observe DOM changes to restore owned controls. They never spoof viewport media queries, edit the site's stylesheets, or move site controls out of their containers.

The content script uses selectors derived from chat links and IDs (`aria-current`, `href`, `data-testid`, and `nav`). These are implementation details of ChatGPT and can change. Keep page-specific selectors in a clearly marked compatibility layer as customization grows.

## Local control server and metadata

The PowerShell server listens on `127.0.0.1:17863`. It requires an exact allowed ChatGPT origin and numeric loopback Host, bounds headers/body/read duration, and handles explicit POST/OPTIONS requests only. PNA permission is returned only for an explicit allowed-origin preflight requesting it; it is retained for compatibility. Browser integration verifies allowed/rejected loopback fetches with local-network permission granted only in the fixture profile.

Pin requests resolve one verified host window. Status reads the actual native topmost style. Mutation requires the target to be foreground, and bound HWNDs are checked with their process ID and the dedicated host profile each time. No foreground window outside that ownership boundary is ever included, and stale on-disk topmost handles are not read. Placement is sampled from the foreground owned window every three seconds and saved as geometry only; launch arguments clamp it to a connected working area.

Enabled session/recent-chat metadata remain local plaintext. Settings control recording, title visibility, and retention; clear-history removes that metadata and legacy URL-bearing logs. New operational logs omit URLs, titles, headers, and request bodies. Recent history always serializes as an array; the taskbar reader accepts legacy singleton objects and applies privacy/retention before displaying entries. Native command-line quoting preserves recent URLs through Windows PowerShell `-File`.

## Visual customization direction

The single override stylesheet carries native-first semantic color tokens (`--app-mode-shell-bg`, `--app-mode-sidebar-bg`, `--app-mode-workspace-bg`, `--app-mode-composer-bg`) plus application radius and spacing properties. Color aliases resolve on the marker body and recognized theme/component boundaries so descendant native theme scopes are respected. The shared page context implements the Codex layout directly: a mounted 52px activity rail visible only while compact, the native docked/drawer sidebar replacing it while expanded, a rounded workspace panel marked on the single rendered content `main`, a centered welcome hero, and a bottom-anchored composer on the blank home route. After validating distinct native welcome/composer branches, the home adapter stretches only their ancestor path and orders the composer after native suggestions, including display-contents variants. The contextual header remains in the workspace column; Electron view bounds provide title-bar separation without a CSS top spacer. Its control surface inherits the workspace token, while the trusted title bar samples the separate shell/title-bar token. ChatGPT's rendered native semantic tokens are authoritative in both appearances, with legacy semantic fallbacks followed by neutral `light-dark()` defaults using the effective inherited `color-scheme`. Explicit native appearance takes precedence over the device preference; System delegates to the site's effective scheme. Native surface variables are never rebound to application colors. Composer colors prefer the native composer surface before elevated-surface compatibility tokens. Native icon-accent, then semantic accent text, supplies custom highlights; readable application text is the terminal fallback. Native text and border tokens preserve supported contrast changes. The isolated controls sampler publishes validated computed colors, including accent, and observes `data-theme`, class/style, media and DOM changes without reading account settings. The main owns the rounded workspace boundary, the contextual header paints its upper corners, and an adjoining recognized content surface paints only its lower corners without new overflow clipping. There is no separate App Mode appearance, accent or contrast preference.

## Native header host

For trusted ChatGPT responses, the host extends `connect-src` to permit its numeric loopback control origin. The effective `default-src` fallback is preserved when `connect-src` is absent; policies with no connection restriction remain unrestricted. This exception applies to connection destinations, not scripts or other resource directives.

Local-network access is automatically allowed only for a trusted main-frame ChatGPT request so the local control endpoint can work. Optional media, clipboard, and notification grants require native consent. Consent is tied to the requesting document and expires on main-frame navigation.

All launch paths use `WindowHost/main.cjs` through `Start-AppModeNativeHost`. The runtime is pinned in `package-lock.json`, installed by `Install-WindowHost.ps1`, and remains untracked under `node_modules/electron/dist`.

The native host composes each window from the existing two isolated `WebContentsView`s. The full-width trusted title bar (`WindowHost/controls.html`, `controls.css`, `controls.js`) owns Sidebar and Search affordances, window dragging, Pin, minimize, maximize/restore, and close. Navigation buttons delegate to ChatGPT's existing native handlers; they do not own independent sidebar state or native menus. `WindowHost/controls-host.cjs` places it at `(0, 0, width, 40)` in native DIPs and sets its zoom to 1. ChatGPT starts at `(0, 40)` and fills the remaining content height. Resize, maximize/restore, fullscreen, display metrics, movement between displays, and page zoom trigger layout. Fullscreen hides the title bar and gives ChatGPT the full content rectangle.

ChatGPT owns its contextual header, Chat/Work switch, menus, and native handlers below the title bar. `WindowHost/header.js` and `header.css` retain compatibility for recognized switch structures in their original containers, without page drag regions, caption reservations, or viewport-wide header bleed. Unknown markup retains native controls. Native window actions remain available even when page matching fails. Do not add another 40px CSS spacer: the view bounds already reserve that space.

The validated action channel accepts only minimize, maximize, restore, close, pin, toggle-sidebar, and open-search. The latter two are separately allowlisted navigation identifiers mapped by the main process to fixed page-local adapter calls; callers cannot supply JavaScript, selectors, URLs, window IDs, or handles. Navigation additionally requires the live attached ChatGPT view, an allowed main-frame origin, completed override injection, and a bounded in-flight action. Document generations reject stale results after full navigation. It checks the exact action, sender webContents, trusted local main frame and document URL, and association with the live owning window; requests carry no window IDs or native handles. The trusted caption renderer is sandboxed with a narrow preload, while remote ChatGPT still has no preload or privileged IPC. Native events synchronize maximize and Always-on-Top state. The host sends compact sizing based on native window width, independently of page zoom. The existing event-driven isolated sampler reads validated computed theme colors and a minimal navigation capability/status record (compact/docked/drawer/unavailable plus booleans), never page text or account/conversation data. That status is an untrusted presentation hint, not authorization for native actions. The page adapter rechecks native action availability and modal blocking on every invocation. Existing reconciliation publishes rendered state without a new polling loop or permanent observer. Title-bar readiness and visibility control reversible page replacement markers; fullscreen, unavailable controls, and unsupported markup restore page entry points. Native drawer dismissal remains inside its focus trap, while title-bar navigation steps back. The original ChatGPT dropdown remains page-owned; recognized docked headers can shrink from 40 to 28 CSS pixels, but unknown controls and modal drawer headers retain their space. The caption session denies permissions and external resources, blocks navigation, and is destroyed with its owner.

The dedicated `Browser/AppModeHostProfile` is derived from the installation root. Remote pages run sandboxed with context isolation, no Node integration, no preload, and no privileged IPC. Only exact ChatGPT pages receive the shared CSS/JS. Sign-in origins are explicitly listed in `WindowHost/policy.cjs`; other validated HTTPS links open externally. Permission checks validate both top-level and requesting origins; optional grants require native consent and expire on main-frame navigation. Downloads use a native Save dialog.

Native window ownership requires the exact Electron executable beneath this installation, exactly one matching root flag, exactly one matching dedicated profile flag, and a browser process rather than a renderer. Existing PID/HWND revalidation and the strict loopback server boundary remain in place. The host's fixture test exercises native input only against verified disposable fixture windows and refuses covered-window clicks.

## Pin ownership and fallback

In Electron App Mode, the visible Pin belongs to the trusted host title bar. It invokes the validated `pin` action in `WindowHost/controls-host.cjs`, which toggles Always-on-Top on the owning `BrowserWindow` and publishes native state back to the title bar. It does not grant the remote page access to that privileged channel.

The shared scripts still maintain the page-owned Pin for the supported standalone extension/hostless environment. Shared CSS uses `var(--app-mode-page-pin-display, grid)` so the page control defaults to visible; only the host stylesheet sets that property to `none`. Electron therefore shows one host Pin without a visible page duplicate, while a context with no title bar retains the functional page fallback. The fallback uses the existing validated loopback control endpoint, window-binding checks, retry behavior, and page shortcut; keeping it mounted also preserves that lifecycle in the host environment. Do not hide it unconditionally in shared CSS or expose the caption preload to the remote page.

`tests/visual.spec.js` covers both presentations. Its standardized-action-row fixture loads the actual caption document with a mocked native bridge, checks mouse/keyboard activation, and verifies fallback visibility when host styling is removed; hostless fixtures cover the page control's recovery and replacement behavior. `tests/window-host.cjs` separately exercises the actual host Pin listener and native Always-on-Top state while checking that the page duplicate stays hidden. Fixture bridge checks alone are not native-window evidence.

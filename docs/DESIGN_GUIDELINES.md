# Design guidelines

Use two distinct header levels: Electron owns a full-width 40 DIP application title bar, and ChatGPT owns the contextual row beneath it. The [header architecture](ARCHITECTURE.md#native-header-host) defines view bounds, fullscreen behavior, and the trusted native-control boundary. Keep restrained, theme-aware control states and visible keyboard focus. Follow the canonical [Pin ownership and fallback](ARCHITECTURE.md#pin-ownership-and-fallback) rule.

- Use consistent spacing steps and align related controls to shared edges.
- Follow ChatGPT's selected appearance, accent and supported contrast through native semantic colors; neutral colors are fallback values, not a required palette. Known sidebar buttons sort before sibling new-chat controls; unmatched site markup keeps its original order.
- Keep the contextual header associated with the conversation workspace. Recognized fixed mode switches use the available content region and fall back to flow when actions would collide. Native title-bar controls remain accessible independently of page zoom; identity may truncate at narrow widths.
- Application-owned surfaces use solid theme-aware fills, subtle borders, and consistent radii. Do not add directional glow or globally remove native gradients, shadows, or pseudo-elements.
- Keep typography readable at normal zoom. Establish a clear hierarchy through size and weight rather than excessive decoration.
- Prefer compact layouts that retain comfortable hit targets, visible focus, and enough room for long conversation content.
- Let the app resize down to narrow windows without clipping essential controls or causing horizontal scrolling. In the trusted title bar, prioritize Sidebar, native window controls, Search, then identity; identity may truncate before the flexible drag region loses its usable minimum. Preserve 40 DIP height and no-drag interactive regions. Keep ChatGPT identity static rather than imitating a dropdown whose native popup cannot live in that view.
- Keep visual clutter low. Add emphasis only where it helps scanning or action recognition.
- Make customization reversible and provide sensible defaults. Hide duplicate Sidebar/Search controls only while a working trusted replacement is available. Retain the original native identity dropdown and modal drawer dismissal; unknown headers retain native space and handlers. Recognized docked headers may shrink to 28px, recovering 12px without moving React-owned controls.
- Support light and dark appearances using semantic tokens and `color-scheme` aware values.
- Scope selectors to the smallest stable region. Avoid broad element-wide overrides and brittle generated class names.
- Check keyboard navigation, focus visibility, reduced motion, contrast, and text zoom along with screenshots.
- Use short color/border transitions and disable them for reduced motion. Keep hover, pressed, and focus feedback free of size changes. Preserve custom theme colors through the existing shared control tokens.
- When ChatGPT markup changes, disable or soften an override that no longer matches instead of applying it globally.
- The Codex surface model uses semantic shell/activity, sidebar, workspace, and elevated composer layers. Resolve shared application colors from native semantic tokens in both light and dark appearances, at recognized scope boundaries rather than only on the body. Use legacy semantic tokens and effective-scheme-aware neutral fallbacks only when current tokens are unavailable. Never write application colors back into native variables. Explicit ChatGPT appearance is authoritative; System follows the site's device-responsive scheme. Keep accent highlights separate from neutral surfaces and retain native contrast, text, message geometry, and composer behavior. See [theme precedence](ARCHITECTURE.md#visual-customization-direction). The activity rail stays mounted but is visible only in compact state; [navigation behavior](NAVIGATION_LAYOUT.md#section-based-navigation-refinement) defines responsive sizing, native disclosures, and the flag-keyed width release. The main owns one rounded boundary: its contextual header carries the top corners and an adjoining clipped content surface carries only the bottom corners. Keep their backgrounds continuous and do not add overflow clipping that cuts native menus and dialogs. Retain the 52px rail and native message widths; contextual padding must not reserve the rail twice.

# Known limitations and follow-up work

- ChatGPT's DOM is not a supported extension API. The pin uses a best-effort header selector and falls back to a separate flow toolbar if the header disappears. Offline screenshots and re-render tests do not prove authenticated live layout compatibility.
- The pin shortcut (Alt+Shift+P) works within a focused ChatGPT page, not as a system-wide Windows hotkey. Native pinning is restricted to a verified window from the dedicated host profile. Separate windows can have different pin states; background mutation requests are rejected.
- Pinned-window fading uses native whole-window alpha, with a default of 30% opacity and a 200ms focus/pointer poll. Settings can disable it or choose 10-100% opacity. Full opacity returns on focus with the pointer back over the window, unpinning, disabling the feature, or graceful server shutdown. Windows remain clickable. Windows already layered by other tools are skipped to preserve their existing effects. An abrupt server termination can leave a faded window until the control server restarts; its HWND marker allows the replacement server to recover it without trusting saved handle files.
- The server accepts only exact `https://chatgpt.com` and `https://chat.openai.com` origins and its numeric loopback Host. Origin checks protect against arbitrary websites, not malicious local software that can spoof HTTP headers. It has no remote listener or arbitrary-command endpoint.
- The private-network grant is retained only for an explicit PNA preflight from an allowed origin. Raw HTTP tests cover the grant and its rejection for untrusted origins. Browser integration covers actual allowed/rejected loopback fetches with local-network permission granted in the isolated test context. Browser versions or enterprise policy may still require the user to allow local-network access; a CORS header cannot bypass that permission.
- Last-session and recent-chat metadata are local plaintext when enabled. Recording, title visibility, and retention are configurable. Clear saved history also removes old URL-bearing logs. New launch/server logging does not include chat URLs, titles, payloads, or headers. Windows shell history can retain metadata until the jump list refreshes.
- Remembered placement samples the foreground App Mode window every three seconds. Very fast moves followed by closing the window may not be captured. Saved placement applies on a fresh window launch.
- Reset is intentionally limited to the dedicated `Browser/AppModeHostProfile`. It refuses links/junctions, software directories, and running host processes.
- Startup preferences create a per-user Startup shortcut; they do not modify machine-wide startup or require elevation. Multiple installations share the named startup entry, so only one can be selected to start automatically.
- Runtime binaries, profile data, logs, config, and shortcuts remain beside source for portable compatibility and are ignored by Git. Persistent live-review data remain under `test-results/` but outside disposable `test-results/runs/`; ordinary tests clear only the latter.
- Rebuild the taskbar executable and restart the tray launcher after an upgrade to load their new code. Changes to injected overrides require closing and reopening App Mode. Tests compile a disposable taskbar binary without invoking its taskbar-registration entry point.
- Native ownership, stale handles/PIDs, foreground requirements, and independent pin state are covered with deterministic native-call doubles. A real multi-window foreground/pinning check remains manual: Windows can refuse to foreground an automated window even when its page reports focus. The tests do not weaken that guard or manipulate the user's active windows.
- Visual snapshots depend on the browser runtime, Windows fonts, GPU drivers, and OS version. Use the lockfile and a consistent Playwright browser. Snapshot tolerance is limited to 50 pixels so a small injected control cannot move unnoticed.

# Native header host limitations

- The application title bar is a fixed 48 CSS-pixel strip above the page view and follows page zoom. The site's own header is normalized in place into a 40px secondary action row; unrecognized header markup keeps the site's native layout instead. Site tooltips intersecting this compact header are suppressed to avoid obscuring its controls.
- The pin button remains an app-injected page control in the secondary row rather than part of the trusted title-bar view. Moving it into the privileged surface would need a narrowly scoped authenticated host channel; that is deferred follow-up work.
- Narrow windows now use the site's genuine responsive layout (slideover sidebar, compact controls) rather than a simulated desktop viewport. The compact header targets a minimum logical viewport of 390 CSS pixels. Increasing page zoom in an already narrow native window can leave less space than that; a 390px-wide window at 150% page zoom provides only about 260 CSS pixels. Widen the window or reduce page zoom to retain the full header. No site actions are hidden to accommodate that extreme combination. Page zoom tests do not establish Windows display-scaling or multi-monitor behavior.
- Custom HTML maximize buttons do not provide the native Windows 11 Snap Layout hover menu. No native hit-test shim is installed. Windows snapping shortcuts (Win+Z and Win+Arrow), edge dragging, and multi-monitor placement require manual checks on the target Windows configuration; do not infer those results from automated maximize/restore tests.
- The installer no longer writes retired Chromium `flags`. Existing custom/legacy keys are preserved during configuration merging. `chromiumPortableRoot` remains a compatibility name used internally by shared reset guards; the Electron runtime boundary is `node_modules/electron`. It is not a supported host selection setting.

- The native host requires Node.js 22.12+ for installation and its pinned Electron runtime; it is the only supported host. A missing runtime or an immediate nonzero startup exit warns and aborts the launch; failures after the 1.5-second startup check need a manual reinstall with `Install-WindowHost.ps1`.
- Sign in separately in the native host. Its dedicated profile does not share sessions with any other browser. `Reset-AppMode-HostProfile.ps1` deletes that profile only.
- Offline native-window tests cover caption buttons, dragging, border resizing, pinning through the real isolated loopback server, narrow layout, navigation and sandbox boundaries. They do not establish actual ChatGPT authentication, every third-party sign-in path, voice/video, or authenticated site layout. Those remain manual live checks.
- The shared header selectors are best-effort. If ChatGPT changes them, a fallback toolbar is used; the application-owned title bar remains independent of the page DOM. Mode switches use a compact single row at narrow widths. Additional site controls or a changed header structure may require updating the scoped normalization.

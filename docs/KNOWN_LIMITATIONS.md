# Known limitations and follow-up work

- ChatGPT's DOM is not a supported extension API. The pin uses a best-effort header selector and falls back to a separate flow toolbar if the header disappears. Offline screenshots and re-render tests do not prove authenticated live layout compatibility.
- The pin shortcut (Alt+Shift+P) works within a focused ChatGPT page, not as a system-wide Windows hotkey. Native pinning is restricted to a verified window in the configured Chromium profile. Separate windows can have different pin states; background mutation requests are rejected.
- Pinned-window fading uses native whole-window alpha, with a default of 30% opacity and a 200ms focus/pointer poll. Settings can disable it or choose 10-100% opacity. Full opacity returns on focus with the pointer back over the window, unpinning, disabling the feature, or graceful server shutdown. Windows remain clickable. Windows already layered by Chromium/other tools are skipped to preserve their existing effects. An abrupt server termination can leave a faded window until the control server restarts; its HWND marker allows the replacement server to recover it without trusting saved handle files.
- The server accepts only exact `https://chatgpt.com` and `https://chat.openai.com` origins and its numeric loopback Host. Origin checks protect against arbitrary websites, not malicious local software that can spoof HTTP headers. It has no remote listener or arbitrary-command endpoint.
- The private-network grant is retained only for an explicit PNA preflight from an allowed origin. Raw HTTP tests cover the grant and its rejection for untrusted origins. Browser integration covers actual allowed/rejected loopback fetches with local-network permission granted in the isolated test context. Browser versions or enterprise policy may still require the user to allow local-network access; a CORS header cannot bypass that permission.
- Last-session and recent-chat metadata are local plaintext when enabled. Recording, title visibility, and retention are configurable. Clear saved history also removes old URL-bearing logs. New launch/server logging does not include chat URLs, titles, payloads, or headers. Windows shell history can retain metadata until the jump list refreshes.
- Remembered placement samples the foreground App Mode browser window every three seconds. Very fast moves followed by closing the window may not be captured. Saved placement applies on a fresh window launch; an already-running Chromium process can impose its own restore behavior.
- Reset is intentionally limited to dedicated profiles beneath this installation's Browser folder (plus the legacy portable Data directory). It refuses links/junctions, software directories, and running browser processes. External custom profiles need manual management.
- Startup preferences create a per-user Startup shortcut; they do not modify machine-wide startup or require elevation. Multiple installations share the named startup entry, so only one can be selected to start automatically.
- Runtime binaries, browser data, logs, config, and shortcuts remain beside source for portable compatibility and are ignored by Git. Persistent live-review data remain under `test-results/` but outside disposable `test-results/runs/`; ordinary tests clear only the latter.
- Rebuild the taskbar executable and restart the tray launcher after an upgrade to load their new code. Changes in extension loading require closing and reopening App Mode. Tests compile a disposable taskbar binary without invoking its taskbar-registration entry point.
- Native ownership, stale handles/PIDs, foreground requirements, and independent pin state are covered with deterministic native-call doubles. A real multi-window foreground/pinning check remains manual: Windows can refuse to foreground an automated browser even when its page reports focus. The tests do not weaken that guard or manipulate the user's active windows.
- Visual snapshots depend on the Chromium runtime, Windows fonts, GPU drivers, and OS version. Use the lockfile and consistent browser runtime. Snapshot tolerance is limited to 50 pixels so a small extension control cannot move unnoticed.
# Native header host limitations

- The native host requires Node.js 22.12+ for installation and its pinned Electron runtime. Chromium remains the explicit rollback (`windowHost: chromium`). Missing runtimes and immediate nonzero startup exits warn and use Chromium; failures after the 1.5-second startup check need manual rollback.
- Sign in separately in the native host. Its dedicated profile does not reuse Chromium sessions, browser extensions, or browser settings. The current reset command continues to apply only to Chromium.
- Offline native-window tests cover caption buttons, dragging, border resizing, pinning through the real isolated loopback server, narrow layout, navigation and sandbox boundaries. They do not establish actual ChatGPT authentication, every third-party sign-in path, voice/video, or authenticated site layout. Those remain manual live checks.
- The shared header selectors are best-effort. If ChatGPT changes them, a fallback toolbar is used; native caption controls remain available. Mode switches use a compact single row at narrow widths. Additional site controls or a changed header structure may require updating the scoped normalization.
- The native host builds in the shared page overrides. The Chromium extension toggle does not disable the host's header integration.
